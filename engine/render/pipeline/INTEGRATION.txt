Lane 09 — render-pipeline — cross-lane integration notes
=========================================================

Wave C update (encoder wiring): all five encode_*() helpers now issue real
psy::gpu::* encoder calls (begin_render / bind_pipeline / push_constants /
dispatch / draw_indexed / end_render). The diagnostic-only fallthrough
remains only when (a) the device hook is null (unit-test headless mode)
or (b) the per-pass shader pipeline failed to compile (e.g. running tests
from a working directory where the relative shader path doesn't resolve).

Files inside engine/render/pipeline/:

  * PublicRenderPipeline.h    — FROZEN contract (untouched; Wave 0)
  * Pipeline_internal.h       — adds depth_only_graphics PSO handle to
                                HizPyramid; adds Pipeline::PassStats counter
                                struct + pipeline_stats() accessor
  * Pipeline.cpp              — render() now orchestrates THREE cmd buffers:
                                  cmd_compute : light_cluster_build + gpu_cull
                                  cmd_depth   : depth pre-pass + HiZ downsample
                                  cmd_opaque  : opaque forward+ render pass
                                Extract is wrapped in a JobSystem submit so
                                Lane 04 can parallelise it once the work-
                                stealing scheduler ships.
  * Resources.cpp             — drops the new depth_only_graphics pipeline
                                on shutdown.
  * Extract.cpp               — unchanged from Wave B (M1 triangle path).
                                M2+ ECS walk pseudocode unchanged.
  * LightCluster.cpp          — encode_light_cluster_build issues
                                  bind_pipeline + push_constants(ShaderStage::Compute)
                                  + dispatch(cluster_count, 1, 1).
  * Hiz.cpp                   — encode_depth_prepass issues
                                  begin_render(depth-only target) +
                                  bind_pipeline(depth_only_graphics) +
                                  push_constants(view_proj+world, Vertex stage) +
                                  draw_indexed(per visible instance) +
                                  end_render.
                                encode_hiz_downsample issues
                                  bind_pipeline(downsample_compute) +
                                  per-mip push_constants + dispatch(8x8 tiles).
  * GpuCull.cpp               — encode_gpu_cull issues
                                  bind_pipeline + push_constants(instance_count) +
                                  dispatch(ceil(N/64), 1, 1).
  * OpaquePass.cpp            — encode_opaque issues
                                  begin_render(swapchain color + pre-pass depth) +
                                  set_viewport / set_scissor +
                                  bind_pipeline(m2_forward, fallback m1_passthrough) +
                                  per-renderable: bind_vertex_buffer + bind_index_buffer
                                  + push_constants(view_proj+world, AllGfx) + draw_indexed +
                                  end_render.
  * shaders/forward.slang     — unchanged from Wave B.
  * shaders/light_cluster_build.slang — unchanged.
  * shaders/hiz_build.slang   — unchanged.
  * shaders/gpu_cull.slang    — unchanged.
  * shaders/depth_only.slang  — NEW; VS-only depth pre-pass shader. The
                                push-constant block matches DepthPushConstants
                                in Hiz.cpp (view_proj + world_matrix = 128B).
  * PipelineSmoke.cpp         — unchanged (headless smoke binary).
  * CMakeLists.txt            — unchanged.

CROSS-LANE GAPS / ISSUES STILL OPEN AFTER WAVE C
═══════════════════════════════════════════════════════════════════════

Issue lane09-001  (UNBLOCKED) — Lane 07 cmd encoder APIs landed
                  (begin_render / bind_pipeline / push_constants /
                  dispatch / draw_indexed / end_render). Closed in Wave C.

Issue lane09-002 — Against orchestrator (FROZEN contract amend)
  Title: Pass psy::gpu::Device* through render::pipeline::PipelineDesc
  Body : Still using the process-wide set_device_hook(Device*) shim.
         No regression in Wave C — the shim works; just architecturally
         awkward. Orchestrator coordinates the cascade when M2 ships.

Issue lane09-003 — Against lane 06 (scene)
  Title: Publish canonical render-side component schema in GxComponents.h
  Body : Extract.cpp expects TransformWS + MeshRef + MaterialRef. Until
         lane 06 ships engine/scene/GxComponents.h with those components,
         the M2+ ECS walk stays commented-out pseudocode. Lane 09 falls
         back to the M1 hardcoded triangle. Status: GxComponents.h is
         partially present (sizes test in tests/unit/) but the render
         schema fields aren't published yet.

Issue lane09-004 — Against lane 08 (shader)
  Title: GraphicsPipelineDesc lacks vertex-layout descriptor
  Body : PublicShader.h::GraphicsPipelineDesc has a comment "// Vertex
         layout supplied via a separate descriptor (TBD by lane 09)" but
         no field. Currently the Metal backend uses an implicit
         [[buffer(N)]] layout in the .slang sources; Vulkan will need an
         explicit VkPipelineVertexInputStateCreateInfo eventually.
         Suggested fields (carried over from Wave B):
           VertexInputAttr / VertexInputBinding arrays.

Issue lane09-005 — Against lane 11 (render-post)
  Title: Coordinate HDR colour attachment ownership
  Body : Opaque pass at M2 wants an HDR R16G16B16A16 colour attachment
         that lane 11's bloom + tonemap reads. Wave C still targets the
         swapchain (Bgra8Srgb) directly. Need to align on HDR target
         ownership + format before M2.

Issue lane09-006 — Against orchestrator / lane 08 (shader VFS)
  Title: Absolute shader path resolution / VFS lookup
  Body : shader_path() emits paths relative to the working directory
         ("engine/render/pipeline/shaders/foo.slang"). Tests run with
         build/mac/tests/unit as the cwd and fail to resolve. M0 sample
         + smoke binary run from the repo root and resolve fine, but
         the unit test relies on a working-directory convention rather
         than a content-addressable VFS path. Resolved by:
           - Lane 08 grows a VFS-rooted slang_path resolution, OR
           - Lane 25 sets WORKING_DIRECTORY ${CMAKE_SOURCE_DIR} for
             catch_discover_tests (single-line change).
         The render_pipeline_smoke test is tolerant of either outcome
         (asserts no-crash; relaxes draw-count check when shaders failed
         to compile).

Issue lane09-007 — Against lane 07 (gpu)
  Title: Metal PSO registration handshake for lane 08 PipelineHandles
  Body : MetalBackend.mm:bind_pipeline logs once per unique handle id
         that lane 08 owes psynder_gx_mtl_register_render_pso. Until
         that handshake ships, all bind_pipeline calls in lane 09's
         encode_*() helpers no-op silently — the pass scope opens, the
         encode walk completes, draw_indexed has c->bound_render_pso=nil
         and skips, and end_render closes the scope cleanly. M2 ship
         depends on this registration. Lane 09's draws + dispatches
         all walk regardless (they're cheap on the CPU side, just
         render nothing on screen).
